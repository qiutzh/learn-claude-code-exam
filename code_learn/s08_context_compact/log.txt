## 命名规律总结

**统一格式**：`s序号: 英文主题名 — 中文副标题`

1. **前缀固定**：`s01`~`s05` 序号 + 英文冒号 + 空格，保证按顺序排列时可读、可导航（正文中的导航链 `s01 → s02 → s03…` 也依赖此编号）。
2. **英文部分与目录名严格 1:1 对应**：主题词即目录名（`Agent Loop`、`Tool Use`、`Permission`、`Hooks`、`TodoWrite`），不翻译、不改写，方便直接定位到对应代码目录。
3. **中文部分用 "—"（破折号）引出**：是一句口语化、有画面感的副标题，概括该节的核心思想而非仅罗列名词。
4. **副标题的视角有规律**：
   - s01–s04 是**解决方案式口号**，直接点出本章机制的定位与收益："一个循环就够了"、"只加一行"、"执行前做权限判断"、"挂在循环上，不写进循环里"；
   - s05 是**痛点式**表述（"没有计划的 Agent，做着做着就偏了"），先讲问题再引出方案。
5. **内容上环环相扣**：副标题反复回扣 s01 建立的"循环"主线（循环、加工具、权限门槛、hook 不侵入循环、计划防跑偏），并分别对应正文中 `**Harness 层**` 那一行的关键词：循环 → 工具分发 → 权限 → hook → 规划。
6. **层级一致**：每篇 README 有且仅有一个 `#` 一级标题，正文从 `##` 二级标题开始（如 `## 问题`、`## 解决方案`），标题层级的阶梯严格统一。

## 顶层结构

```json
[                          // 顶层是一个 JSON 数组
  {
    "version": "s01",
    "locale": "en",
    "title": "s01: The Agent Loop — One Loop Is All You Need",
    "content": "# s01: The Agent Loop — One Loop Is All You Need\n\n..."
  },
  ...
]
```

| 属性 | 值 |
|---|---|
| 顶层类型 | **数组**（list），共 **51 条**记录 |
| 记录条数 | 51 = **17 门课程（s01–s17）× 3 种语言（en / zh / ja）** |
| 每条记录的字段 | 固定 4 个：`version`、`locale`、`title`、`content` |

即：**一门课程的完整资料 = 3 条记录**（每语言一条），记录唯一标识是 `(version, locale)` 组合。

## 一条课程记录的 4 个主要字段

### 1. `version`
- 字符串，取值 `"s01"` ~ `"s17"`。
- 课程编号，与源码目录名尾部一一对应（`s01_agent_loop`、`s02_tool_use`…）。

### 2. `locale`
- 语言标识，只有 `"en"`、`"zh"`、`"ja"` 三种取值。
- 决定前端展示哪份内容，也决定 `content` 内图片和导航链接的语言变体。

### 3. `title`
- 该语言版本的**一级标题**，即上一篇对话中讨论的 `# s01: Agent Loop — 一个循环就够了` 这类标题。
- 格式保持 `s编号: 英文主题 — 副标题`（s08/s17 用全角冒号 `：`），与源 README 的 `#` 标题完全一致，同时是页面标题/标签页等界面显示所用的字符串。

### 4. `content`
- **完整的 Markdown 文档正文**（字符串），以与 `title` 相同的 `#` 一级标题开头。
- 内部结构（以 zh/s01 为例）：
  ```
  # s01: Agent Loop — 一个循环就够了
  ## 问题
  ## 解决方案
  ## 工作原理
  ## 试一下
  # 编辑 .env，填入 ANTHROPIC_API_KEY 和 MODEL_ID
  ## 接下来
  ```
  特点：
  - 全站只使用 `#`、`##`、`###` 三级标题；
  - 各语言版本**章节数严格一致**（s01/s08/s17 的 `##` 数分别为 5/16/11，三种语言相同），只是文字被本地化；
  - 顶部有导航行 `` `s01` → [s02](/en/s02) → s03 → … ``，链接按语言生成（`/en/s02`、`/zh/s02`、`/ja/s02`）；
  - 插图引用绝对路径 `/course-assets/<目录>/<主题>.{locale}.svg`，如 `/course-assets/s01_agent_loop/agent-loop.en.svg`，同时存在不带语言后缀的通用回退版本；
  - 内容体量：en 平均约 8.7K 字符（4.5K~20K），zh 平均约 5.5K（3.1K~11.7K），ja 平均约 6.5K。

## 与同目录其它文件的关系

`web/src/data/generated/` 下还有 `versions.json`（顶层是包含 `versions`、`diffs` 两个键的对象）：其中 `versions` 记录每条课程的 `id`、`filename`、`title`、"subtitle" 等元数据，供侧边栏/课程路径页使用；而 `docs.json` 则是各语言**全文内容**的集合，二者配合由前端渲染课程页面。

## 命名规律总结

1. **统一三段式结构：`s<NN>: <能力名> — <一句口诀>`**
   - `s01`~`s05` 编号前缀：对应课程顺序，也用在了目录名上（如 `s01_agent_loop`、`s05_todo_write`）。
   - 主标题是一个简短的名词短语，且**一课只命名一个新增的 harness 能力/层次**（循环、工具、权限、钩子、计划）。
   - 用破折号（—，em dash）把标题和副题隔开，排版上全系列一致。

2. **副题都是一句可独立记忆的"设计原则/断言"，而非实现说明**，且各有固定句式风格：
   - **s01 主张极简**："One Loop Is All You Need"（化用 *Attention Is All You Need*），强调一个循环就够。
   - **s02 强调低成本扩展**："Just One Line"，突出接入一个新工具的成本极低。
   - **s03 是祈使句规则**："Check Permissions Before Execution"，直接给出执行前必须做的一件事。
   - **s04 用空间隐喻 + 祈使句**："Hang on the Loop, Don't Write into It"，说明扩展方式（挂接而非侵入）。
   - **s05 是条件因果句**："An Agent Without a Plan Drifts Off Course"，点出"无计划 → 跑偏"的问题。

3. **主标题按"能力层次递增"排列**：从核心执行循环（s01）→ 给循环加能力（s02 工具）→ 加护栏（s03 权限）→ 加扩展点（s04 钩子）→ 加自我组织（s05 计划），对应课程逐步构建 harness 的递进线索。

4. **标题与目录名同构**：目录名就是主标题概念的 snake_case 形式（`s01_agent_loop`、`s02_tool_use`、`s03_permission`、`s04_hooks`、`s05_todo_write`），形成 "编号 + 概念" 的双重索引，便于按序和按名定位。
