## Code Review: code_s07.py

### Summary
一个用于演示"技能按需加载"机制的最小 Agent 运行框架（SkillLoader 扫描 + 工具分发 + 钩子系统 + Anthropic API 循环）。整体结构清晰、可读性好，但存在 1 个会导致 3/4 技能无法被正确描述的关键缺陷，以及若干安全与健壮性问题。

### Critical Issues

1. **frontmatter 解析失败 → 技能描述退化为 "```markdown"**（`parse_frontmatter`，第 60–63 行）
   - 根因：`code-review`、`mcp-builder`、`pdf` 三个 SKILL.md 以 ```` ```markdown ```` 围栏行开头，而不是 `---`。`lines[0].rstrip("\r\n") != "---"` 直接判定无 frontmatter，回退逻辑 `body.split("\n", 1)[0]` 取到首行即 ```` ```markdown ````，于是 `catalog()` 输出三个废话描述（`agent-builder` 因文件以 `---` 开头而侥幸正常）。已实测确认。
   - Impact：系统提示中的技能目录失去真正描述，模型无法判断何时该加载技能——这正是本程序要演示的核心功能，等于功能失效。
   - Fix：解析前先剥离围栏行；或在全文查找第一个行首 `---` 作为 frontmatter 起始：
     ```python
     text = text.strip()
     if text.startswith("```"):
         text = text.split("\n", 1)[1]  # 去掉首个围栏
     lines = text.splitlines(keepends=True)
     ```

2. **DENY_LIST 匹配为大小写敏感的子串匹配**（`permission_hook`，第 211 行 `if pattern in command`）
   - Impact：Windows 下 cmd 命令不区分大小写，`SHUTDOWN`、`Sudo`、`MKFS` 等可绕过拒绝名单（而 `rm`/`del` 走的大小写不敏感正则却能拦截）。同时 "sudo" 子串匹配会把无害命令（如 `echo sudo`）也误拦。
   - Fix：`if pattern.lower() in command.lower():`，或统一改用与 `DESTRUCTIVE_COMMAND_WORD` 一致的单词边界正则。

3. **`run_bash`（shell=True）不受工作区路径限制**（第 152–161 行）
   - Impact：文件类工具（read/write/edit/glob）都有 `is_relative_to(WORKDIR)` 包含检查，但 bash 工具没有任何沙箱约束，模型可借 shell 读取/改写工作区外的任意文件、环境变量（含 API key）——沙箱逃逸。
   - Fix：至少将 bash 的越权风险纳入权限钩子询问；更强的方案是限制 `cwd` 并在子进程中降权，或使用无 shell 的 API + 白名单。

## README.md 内容概要（s07: Skill Loading）

对应路径 `code_official\s07_skill_loading\README.zh.md`（当前工作目录本身没有 README）。要点：

- **问题**：把所有规范文档（React 规范、SQL 指南、API 设计文档）全部塞进 system prompt，会导致每次调用都发送无关全文，浪费 token 和上下文窗口。
- **解决方案**：分两级加载——
  1. 启动时 `SkillLoader` 扫描 `skills/*/SKILL.md`，只把 `name` + `description` 目录放入 system prompt；
  2. 模型按需调用 `load_skill(name)`，完整 SKILL.md 以 `tool_result` 形式追加到消息。
- **涉及机制**：frontmatter 解析、`catalog()`、`load()`（按名字查注册表而非路径）、Agent Loop 中 tool_result 的追加。

## 已加载的相关技能：agent-builder

根据其描述中的使用场景——"需要关于**能力、子智能体、规划或技能机制（skill mechanisms）**的帮助"以及"询问 Claude Code 或类似**智能体内部机制**"——README 讲的正是技能加载机制本身，因此 agent-builder 是唯一直接相关的技能（code-review / mcp-builder / pdf 均不相关）。

## 用 agent-builder 的视角解读 README

agent-builder 的核心理念与此 README 的设计完全对应：

1. **"知识按需加载（Front-loaded knowledge 是反模式）"**：README 解决的问题正是技能的反模式——"前置知识导致上下文膨胀"。解决方式是把知识目录（名称+摘要）放入 context，让模型决定何时加载全文。这与"让知识可用，而非强制；在相关时加载，而非预先加载"一致。
2. **三大要素对应关系**：
   - **能力**：`load_skill` 是一个原子工具，入口在 TOOLS 列表，处理在 `TOOL_HANDLERS`。
   - **知识**：各 `SKILL.md` 是按名称登记的领域知识，注入方式是 tool_result。
   - **上下文**：目录很小（仅名称+描述），只有在相关时才把全文追加进消息——保护上下文清晰性。
3. **"模型就是智能体"**：README 明确展示了系统不预先加载所有内容，而是给模型一个目录并信任它能判断何时需要。
4. **渐进式复杂度第 4 层（技能：按需知识）**：s07 实现的正是这一层——"需要领域专业知识时"才添加按需加载的技能。
